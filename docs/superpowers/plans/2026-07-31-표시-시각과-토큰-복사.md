# 표시 시각과 토큰 복사 Implementation Plan

> **For agentic workers:** codex 워커에게 카드 단위로 위임된다. 각 Task는 브랜치로 격리하고, 검증 명령이 모두 통과한 뒤 Claude의 설계 부합 검토를 거쳐 main에 병합한다.

**Goal:** 화면의 날짜·시각을 한국 시각으로 맞추고, 한 번만 표시되는 등록 토큰을 버튼으로 복사할 수 있게 한다.

**전제:** 운영 중이다. 두 Task 모두 DB 스키마 변경이 없다.

## Task A — 표시 시각을 한국 시각으로

### 지금 무엇이 잘못됐나

2026-07-31 기준 확인 결과다.

- `deployhub-web` 컨테이너의 TZ가 **UTC**다. `TZ` 환경변수는 비어 있고 `/etc/timezone`도 없다.
- 화면의 날짜 포맷터 **7곳**이 전부 아래와 같고, `timeZone`을 지정하지 않는다.

```ts
const DATE_FORMAT = new Intl.DateTimeFormat('ko-KR', {
  dateStyle: 'medium',
  timeStyle: 'short',
});
```

`ko-KR`은 **표기 방식**만 정한다. 어느 시간대로 환산할지는 정하지 않으므로 런타임 TZ, 즉 UTC가 쓰인다. 결과적으로 모든 시각이 **9시간 밀려** 표시된다. 7곳의 옵션이 한 글자도 다르지 않다.

| 파일 |
|---|
| `apps/web/src/app/projects/[slug]/page.tsx:49` |
| `apps/web/src/app/settings/drafts/page.tsx:27` |
| `apps/web/src/app/settings/providers/components/provider-account-card.tsx:4` |
| `apps/web/src/app/settings/resources/page.tsx:28` |
| `apps/web/src/app/settings/tokens/page.tsx:22` |
| `apps/web/src/components/events/timeline-list.tsx:4` |
| `apps/web/src/components/schematic/project-sheet.tsx:8` |

DB는 전부 `timestamptz`라 저장된 값은 정확하다. **표시 계층만의 문제이고 데이터 보정은 필요 없다.**

### 결정

| 항목 | 결정 | 근거 |
|---|---|---|
| 고치는 위치 | **공용 모듈 하나를 만들고 7곳이 그것을 쓴다** (`apps/web/src/lib/datetime.ts`) | 같은 리터럴을 7번 반복하면 다음에 또 한 곳이 빠진다. 이번 버그가 정확히 그 모양이다 |
| 시간대 지정 방법 | **`timeZone: 'Asia/Seoul'` 을 포맷터에 박는다** | 런타임 TZ에 기대지 않는다. 어느 서버에 올려도, 로컬(KST)에서 돌려도 같은 문자열이 나온다 |
| 컨테이너 `TZ` 환경변수 | **쓰지 않는다** | compose에 `TZ=Asia/Seoul` 한 줄이면 되지만, 표시 결과가 배포 환경에 좌우된다. 로컬은 KST라 통과하고 서버는 UTC라 틀리는 지금 상황이 그 위험의 실례다 |
| 뷰어 로컬 시간대 사용 | **하지 않는다** | 클라이언트 렌더링과 hydration 처리가 필요하다. 사용자가 한국에 있는 단일 운영자라 얻는 것보다 복잡도가 크다 |

### 구현

`apps/web/src/lib/datetime.ts` 를 만든다.

```ts
export const DISPLAY_TIME_ZONE = 'Asia/Seoul';

const DATE_TIME_FORMAT = new Intl.DateTimeFormat('ko-KR', {
  dateStyle: 'medium',
  timeStyle: 'short',
  timeZone: DISPLAY_TIME_ZONE,
});

export function formatDateTime(value: Date): string {
  return DATE_TIME_FORMAT.format(value);
}
```

7개 파일에서 각자의 `DATE_FORMAT` 정의를 **지우고** `formatDateTime` 을 import 해 쓴다.
`DATE_FORMAT.format(x)` 호출부를 `formatDateTime(x)` 로 바꾼다. 표기 형식은 바꾸지 않는다.

`provider-account-card.tsx` 는 클라이언트 경계 밖의 서버 컴포넌트다. 새 모듈에
`'use client'` 를 붙이지 않는다.

### 수용 기준

- [ ] `apps/web/src` 안에 `new Intl.DateTimeFormat` 이 `lib/datetime.ts` 한 곳에만 남는다
- [ ] 알려진 UTC 순간이 KST 문자열로 렌더된다. **기대값을 명시적으로 단언한다** — 예: `new Date('2026-07-31T01:00:00Z')` → 오전 10시로 표시
- [ ] 위 테스트가 머신 TZ와 무관하게 통과한다 (로컬 Windows는 KST, 컨테이너는 UTC. 둘 다 같은 결과여야 한다)
- [ ] 7개 화면의 표기 형식이 변경 전과 동일하다 (시간대만 바뀐다)

## Task B — 등록 토큰 복사 버튼

**선행:** Task A와 독립이다. 파일이 겹치지 않으므로 순서는 상관없다.

### 지금

`apps/web/src/app/settings/tokens/token-form.tsx` 가 발급 직후 원문을 `<code>` 블록으로 한 번만
보여준다. 사용자가 드래그해서 복사해야 한다. 토큰은 길고 다시 볼 수 없어서 선택 실수가 곧 재발급이다.

### 구현

이미 `'use client'` 컴포넌트다. 원문 블록 옆에 복사 버튼을 둔다.

- `navigator.clipboard.writeText(state.rawToken)` 을 쓴다
- 상태 3개: 기본 `복사` → 성공 `복사됨` (2초 뒤 기본으로 복귀) → 실패 `복사 실패`
- **`navigator.clipboard` 가 없거나 거부되면 실패 상태를 보여준다.** 조용히 성공한 척하지 않는다. 실패 시에도 원문 블록은 그대로 있어 직접 선택할 수 있다
- 상태 문구에 `aria-live="polite"` 를 준다
- 기존 `Button` 컴포넌트와 디자인 토큰을 쓴다. 새 스타일을 만들지 않는다

### 하지 말 것

- **토큰을 `console.log`, `title` 속성, `data-*` 속성, URL 어디에도 넣지 않는다.** 화면의 `<code>` 블록 하나가 유일한 노출 지점이어야 한다
- 자동 복사(마운트 시 클립보드 쓰기)를 하지 않는다. 사용자가 누른 적 없는 클립보드 쓰기는 놀라운 동작이다
- 복사 성공 후 원문 블록을 감추지 않는다. 붙여넣기가 실패했을 때 확인할 곳이 사라진다

### 수용 기준

- [ ] 원문이 표시될 때만 복사 버튼이 보인다 (`state.rawToken` 이 없으면 버튼도 없다)
- [ ] 클릭하면 `navigator.clipboard.writeText` 가 **토큰 원문 그대로** 호출된다
- [ ] 성공 시 `복사됨` 이 보이고 2초 뒤 원래 문구로 돌아온다
- [ ] `writeText` 가 reject 하면 실패 문구가 보이고, 원문 블록은 그대로 남는다
- [ ] `navigator.clipboard` 가 undefined 인 환경에서 클릭해도 예외가 새지 않는다
- [ ] 렌더된 마크업에서 토큰이 `<code>` 블록 밖에 등장하지 않는다 (속성값 포함)
