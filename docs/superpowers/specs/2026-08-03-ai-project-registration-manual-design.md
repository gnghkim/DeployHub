# AI 기반 프로젝트 등록 매뉴얼 설계

작성일: 2026-08-03

## 목적

DeployHub 사용자가 다른 프로젝트의 등록과 정보 갱신 작업을 AI에게 안전하게
위임할 수 있도록 사용자 중심 매뉴얼을 작성한다. 사용자는 명령어를 모두 외우지
않아도 복사 가능한 요청문으로 작업을 시작하고, AI가 만든 Draft를 검토·승인할 수
있어야 한다.

## 범위

매뉴얼에 포함하는 작업은 다음과 같다.

- 신규 프로젝트를 DeployHub에 Draft로 등록
- 이미 등록된 프로젝트의 현재 상태와 차이 확인
- 기술 구성 또는 배포 정보 변경을 Draft로 동기화
- Draft 검토와 최종 승인
- 등록 실패 또는 정보 부족 시 AI에게 재조사를 요청하는 방법

다음 작업은 포함하지 않는다.

- DeployHub 서비스 자체의 빌드·배포·운영
- 다른 프로젝트의 실제 애플리케이션 배포 실행
- DeployHub 서버 설치 및 인프라 구성

## 독자

두 독자층을 함께 지원한다.

- 비개발 사용자: AI에게 무엇을 요청하고 Draft에서 무엇을 확인해야 하는지 안내
- 개발자·운영자: AI가 따라야 할 CLI 순서, 검증 기준, 비밀정보 취급 원칙 안내

첫 부분에는 비개발 사용자가 바로 따라 할 수 있는 빠른 시작을 배치하고, 뒤쪽에는
기술 절차와 예외 상황을 설명한다.

## 문서 방식

작업 중심형 구성을 사용한다. 사용자가 처한 상황을 먼저 선택하고 해당 요청문을
복사할 수 있게 한다. 각 작업 안에 단계별 흐름과 사용자·AI의 역할을 함께 표시한다.

다음 대안은 채택하지 않는다.

- 단계 중심형만 사용: 전체 흐름은 선명하지만 필요한 요청문을 빠르게 찾기 어렵다.
- 역할 중심형만 사용: 책임은 명확하지만 실제 작업 순서가 여러 곳으로 분산된다.

## 사용자 흐름

1. 사용자가 등록 대상 프로젝트 저장소를 AI 작업 공간으로 연다.
2. 사용자는 매뉴얼의 신규 등록 또는 기존 정보 갱신 요청문을 AI에게 전달한다.
3. AI는 저장소와 운영 설정에서 확인 가능한 근거를 조사한다.
4. AI는 DeployHub CLI를 빌드하고 정해진 순서로 manifest를 생성·검증한다.
5. AI는 검증에 성공한 변경만 Draft로 제출하고 결과와 Draft URL을 보고한다.
6. 사용자는 Draft에서 프로젝트명, 구성요소, Provider, URL, 외부 참조값과 변경 내용을
   확인한다.
7. 사용자가 Draft를 승인하면 등록 또는 갱신이 완료된다.

## 역할과 승인 경계

### 사용자

- 등록 대상과 원하는 작업을 지정한다.
- `DEPLOYHUB_URL`과 `DEPLOYHUB_TOKEN`을 터미널 환경변수로 준비한다.
- AI가 제출한 Draft URL에서 변경 내용을 검토한다.
- 최종 승인 또는 반려를 결정한다.

### AI

- 저장소의 실제 구성과 배포 근거를 조사한다.
- CLI가 생성한 최신 Schema 기반 manifest만 사용한다.
- 불명확한 값을 추측하지 않고 누락 또는 확인 필요 사항으로 보고한다.
- `validate`에 성공한 변경만 Draft로 제출한다.
- 실행한 검사, 발견한 불확실성, Draft URL과 사용자 확인 항목을 보고한다.

AI는 Draft의 최종 승인을 대신하지 않는다.

## 안전 원칙

- `DEPLOYHUB_TOKEN`은 환경변수로만 전달한다.
- 토큰, 비밀번호, Provider Secret을 파일, 명령 인자, 로그 또는 AI 대화에 기록하지
  않는다.
- `provider`, `externalRef`, `container`, `url`은 저장소나 운영 설정에서 확인된 값만
  사용한다.
- 알 수 없는 값은 그럴듯하게 만들지 않는다.
- 검증에 실패한 manifest는 제출하지 않는다.
- 실제 서비스 배포, 데이터 삭제 등 등록 범위 밖의 작업은 별도 승인 없이 수행하지
  않는다.

## 매뉴얼 구성

1. 매뉴얼의 범위와 핵심 원칙
2. 5분 빠른 시작
3. 등록 전에 사용자가 준비할 사항
4. 신규 프로젝트 등록 위임
5. 기존 프로젝트 정보 갱신 위임
6. AI가 따라야 하는 CLI 절차
7. Draft에서 사용자가 확인할 항목
8. 비밀정보 및 추측 방지 원칙
9. 오류·정보 부족 상황별 재요청 방법
10. AI의 완료 보고 예시
11. 상세 기술 문서 링크

## 복사 가능한 요청문

매뉴얼은 최소한 다음 요청문을 제공한다.

- 신규 프로젝트 조사·등록 요청
- 기존 프로젝트 상태 확인·동기화 요청
- Draft 제출 전 검증만 요청
- 누락되거나 추측된 값 재조사 요청
- 검증 오류 원인 진단 요청

요청문은 AI가 등록 범위를 벗어나 실제 서비스를 배포하지 않도록 범위를 명시하고,
비밀정보를 출력하지 않으며, Draft까지만 제출하도록 지시한다.

## 구현 대상

- 새 사용자 매뉴얼: `docs/ai-project-registration-manual.md`
- 문서 탐색 링크: `README.md`의 문서 안내 영역

기존 `docs/project-registration.md`는 CLI 필드와 상세 등록 절차의 기준 문서로 유지한다.
새 매뉴얼은 이를 반복하기보다 사용자 요청문, 역할, 승인 흐름을 중심으로 설명하고
필요한 곳에서 상세 문서로 연결한다.

## 완료 기준

- 비개발 사용자가 첫 요청문을 복사해 등록 작업을 시작할 수 있다.
- 신규 등록과 기존 정보 갱신 흐름이 명확히 구분된다.
- CLI 명령 순서가 저장소의 `AGENTS.md` 지침과 일치한다.
- 토큰을 대화나 명령 인자로 전달하도록 안내하는 내용이 없다.
- 모든 등록·갱신 결과가 Draft와 사용자 승인 단계를 거친다.
- DeployHub 자체 배포 또는 대상 프로젝트의 실제 배포 절차가 포함되지 않는다.
- README에서 새 매뉴얼을 찾을 수 있다.
