# DeployHub README 개편 설계

## 배경

현재 README는 확정 버전과 CLI 사용법을 중심으로 작성되어 있다. DeployHub를
처음 설치하거나 운영하려는 개발자·관리자가 제품의 목적, 주요 기능, 시스템 구성,
로컬 검증 방법을 한 흐름으로 파악하기 어렵다. 배포와 프로젝트 등록에 관한 상세
문서는 이미 존재하므로, README는 진입점 역할에 집중하고 긴 절차는 해당 문서로
연결한다.

## 목표 독자

주 독자는 DeployHub를 처음 설치하거나 운영하는 개발자·관리자다. 저장소에
기여하려는 개발자와 DeployHub CLI로 프로젝트를 등록하려는 사용자는 보조
독자이며, 각각 필요한 명령과 상세 문서로 빠르게 이동할 수 있어야 한다.

## 목표

- DeployHub가 어떤 문제를 해결하는지 첫 화면에서 설명한다.
- 주요 기능과 런타임 구성요소의 관계를 짧고 정확하게 소개한다.
- 저장소에서 확인된 요구사항과 명령만 사용해 로컬 개발·검증 경로를 제공한다.
- 운영 배포, 프로젝트 등록, CLI 게시와 같은 긴 절차는 기존 문서로 연결한다.
- 토큰과 비밀번호 등 비밀값을 안전하게 다루는 원칙을 분명히 한다.
- 기존 확정 버전 정보와 라이선스 정보를 보존한다.

## 비목표

- `docs/deployment.md`의 운영 서버 구축 절차를 README에 복제하지 않는다.
- `docs/project-registration.md`의 manifest 필드 설명과 Draft 승인 절차를
  README에 모두 복제하지 않는다.
- `docs/cli-npm-publishing.md`의 npm 게시 절차를 README에 복제하지 않는다.
- 저장소에서 확인할 수 없는 URL, 환경값, 설치 자동화 또는 지원 범위를 만들지
  않는다.
- 제품 스크린샷이나 별도 시각 자산은 이번 개편 범위에 포함하지 않는다.

## 정보 구조

README는 다음 순서로 구성한다.

1. **소개**: DeployHub를 통합 프로젝트·인프라 관리 시스템으로 설명한다.
2. **주요 기능**: 프로젝트와 구성요소 현황, 상태 점검, 배포 정보, Draft 승인 기반
   등록, 프로젝트 카드 접기 기능을 요약한다.
3. **시스템 구성**: Next.js 웹, 워커, PostgreSQL, Docker Socket Proxy, CLI의
   책임을 간단한 표로 설명한다.
4. **요구사항**: Node.js와 pnpm 버전 요구사항, Docker가 필요한 작업 범위를
   구분한다.
5. **로컬 개발 빠른 시작**: 의존성 설치, 환경 파일 준비, PostgreSQL 시작,
   마이그레이션, 웹과 워커 실행에 필요한 검증된 명령을 안내한다. 저장소에 단일
   통합 개발 스크립트가 없다면 이를 새로 있는 것처럼 설명하지 않고, 실제 패키지
   단위 명령을 사용한다.
6. **검증 명령**: 전체 타입 검사, 테스트, 웹 빌드, CLI 빌드 명령을 제공한다.
7. **CLI 빠른 사용법**: `DEPLOYHUB_URL`과 필요 시 `DEPLOYHUB_TOKEN`을
   환경변수로 전달하고, 신규·기존 프로젝트의 대표 명령 흐름을 보여 준다.
8. **상세 문서**: 운영 배포, 프로젝트 등록, CLI npm 게시, AGENTS 템플릿으로
   연결한다.
9. **기술 스택과 확정 버전**: 기존 표를 README 후반으로 이동해 보존한다.
10. **라이선스**: MIT 라이선스를 표시하고 저장소의 `LICENSE`로 연결한다.

## 내용 경계와 표현 원칙

- 본문은 한국어로 작성하고 명령, 패키지명, 파일명은 원문 표기를 유지한다.
- 첫 방문자가 훑어볼 수 있도록 짧은 문단, 표, 최소한의 명령 블록을 사용한다.
- 자세한 운영 절차보다 목적과 다음 행동을 먼저 보여 준다.
- `.env.example`의 변수 이름은 설명할 수 있지만 토큰, 비밀번호, Provider Secret의
  실제 값이나 그럴듯한 예시는 기록하지 않는다.
- `DEPLOYHUB_TOKEN`은 명령 인자가 아닌 환경변수로만 전달한다고 명시한다.
- CLI manifest 구조를 README에서 임의로 재작성하지 않고 생성·검증 명령과 상세
  등록 문서로 안내한다.
- 프로젝트 카드 접기는 사용자 관점의 기능 설명에만 포함하고 구현 세부사항이나
  브라우저 저장소 키는 노출하지 않는다.

## 정확성 기준

README의 명령과 설명은 다음 파일을 기준으로 한다.

- 루트 `package.json`과 각 워크스페이스의 `package.json`
- `pnpm-workspace.yaml`
- `.env.example`
- `docker/compose.yml`
- `deployhub.yaml`
- `docs/deployment.md`
- `docs/project-registration.md`
- `docs/cli-npm-publishing.md`
- `templates/AGENTS.deployhub.md`

서로 다른 문서의 설명이 충돌하면 실제 스크립트와 구성 파일을 우선하며, 충돌을
README에 그대로 옮기지 않는다.

## 검증

작성 후 다음을 확인한다.

- README의 모든 상대 링크 대상이 존재한다.
- 코드 블록의 명령과 패키지 필터가 현재 `package.json` 스크립트와 일치한다.
- 언급한 환경변수가 `.env.example` 또는 CLI 계약에서 확인된다.
- 토큰, 비밀번호, Provider Secret 등의 실제 비밀값이 포함되지 않는다.
- Markdown 제목 구조와 코드 블록이 올바르게 렌더링된다.
- `git diff --check`가 통과한다.
