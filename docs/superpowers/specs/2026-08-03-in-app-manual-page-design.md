# DeployHub 앱 내 사용 매뉴얼 페이지 설계

작성일: 2026-08-03

## 목적

GitHub에만 있는 AI 프로젝트 등록 위임 매뉴얼을 DeployHub 안에서도 읽을 수 있게
한다. 사용자는 앱을 벗어나지 않고 신규 프로젝트 등록과 기존 정보 갱신 요청문을
복사하고, Draft 검토 절차와 문제 해결 방법을 확인할 수 있어야 한다.

## 범위

- `/manual`에 로그인 사용자를 위한 전체 매뉴얼 페이지 추가
- 기존 `docs/ai-project-registration-manual.md`의 전체 사용자 안내를 웹 화면으로 제공
- 사이드바 하단에 `사용 매뉴얼` 링크 추가
- 긴 문서를 위한 페이지 목차와 섹션 anchor 제공
- AI 요청문을 복사하는 버튼 제공
- 데스크톱과 모바일 레이아웃 지원

다음 항목은 포함하지 않는다.

- DeployHub 자체 배포 매뉴얼
- 대상 프로젝트의 실제 서비스 배포 절차
- Markdown 런타임 렌더링 또는 GitHub iframe
- 매뉴얼 편집용 관리자 UI
- 데이터베이스 스키마 또는 API 변경

## 결정된 접근법

네이티브 React 페이지를 사용한다. 기존 Markdown의 내용을 React 요소로 옮기고
DeployHub의 디자인 토큰과 페이지 패턴을 적용한다.

### 채택 이유

- Next.js standalone 운영 이미지에서 별도 Markdown 파일 경로에 의존하지 않는다.
- Markdown 렌더러 의존성과 HTML 정화 처리가 필요 없다.
- 코드 블록, 복사 버튼, 체크리스트와 반응형 목차를 제품 UI에 맞게 제어할 수 있다.

### 채택하지 않은 대안

- Markdown 직접 렌더링: 단일 원본이라는 장점이 있지만 새 의존성, Docker 파일
  추적 설정과 HTML 안전 처리가 필요하다.
- GitHub 문서 삽입: 구현은 작지만 외부 네트워크와 GitHub UI에 의존하고 앱 안의
  읽기 경험이 떨어진다.

네이티브 페이지와 Markdown은 두 표현을 함께 유지해야 한다. 매뉴얼 내용을 바꿀
때 두 파일을 함께 갱신한다는 주석과 핵심 콘텐츠 테스트를 둔다.

## 내비게이션

기존 주 메뉴의 `프로젝트`, `발견`, `변경`, `설정` 네 항목은 유지한다.
`사용 매뉴얼`은 사이드바 하단의 `System status` 위에 배치한다.

- 링크: `/manual`
- 라벨: `사용 매뉴얼`
- 현재 경로가 `/manual`이면 주 메뉴와 같은 활성 스타일을 적용한다.
- 모바일 drawer에서도 동일한 위치와 링크를 제공한다.
- 링크를 누르면 기존 drawer 닫기 동작을 사용한다.

이 위치는 운영 기능의 위계를 바꾸지 않으면서 전역 도움말을 항상 찾을 수 있게
한다.

## 페이지 구조

`/manual`은 기존 `Topbar`에 `사용 매뉴얼` 제목을 표시한다. 본문에는 다음 순서로
전체 매뉴얼을 제공한다.

1. AI에게 DeployHub 프로젝트 등록 맡기기
2. 이 매뉴얼의 범위
3. 5분 빠른 시작
4. 시작 전에 준비할 것
5. 신규 프로젝트 등록 맡기기
6. 기존 프로젝트 정보 갱신 맡기기
7. AI가 따라야 하는 절차
8. Draft에서 사용자가 확인할 것
9. 비밀정보와 추측 방지 원칙
10. 문제가 생겼을 때 다시 요청하기
11. AI의 완료 보고 예시
12. 더 자세한 문서

신규 등록, 정보 갱신, 검증 전용, 재조사, 오류 진단 요청문은 기존 문서의 의미와
범위를 그대로 유지한다. `DEPLOYHUB_TOKEN`을 대화나 명령 인자로 전달하도록
안내하지 않는다.

## 레이아웃과 반응형 동작

### 데스크톱

- `Topbar` 아래에 최대 너비를 제한한 본문 영역을 둔다.
- 본문과 오른쪽 목차를 두 열로 배치한다.
- 오른쪽 목차는 viewport 안에서 sticky로 유지한다.
- 현재 페이지 목차임을 알 수 있는 접근성 라벨을 제공한다.

### 모바일

- 본문을 한 열로 표시한다.
- 목차를 본문 시작 부분에 배치한다.
- 긴 명령과 요청문 코드 블록은 페이지 폭을 늘리지 않고 가로 스크롤한다.
- 기존 사이드바는 mobile drawer 동작을 그대로 사용한다.

### 콘텐츠 표현

- 안내와 경고는 기존 CSS 변수로 만든 경계선 카드로 구분한다.
- 명령, 환경변수 예시와 AI 요청문은 코드 블록으로 표시한다.
- Draft 검토 항목은 체크리스트로 표시한다.
- 모든 주요 제목에는 안정적인 영문 anchor id를 사용한다.

## 구성요소

### `apps/web/src/app/manual/page.tsx`

- 전체 매뉴얼을 렌더링하는 서버 컴포넌트다.
- 데이터베이스나 외부 네트워크를 사용하지 않는다.
- `Topbar`, 목차, 본문 섹션과 복사 가능한 요청문을 조합한다.
- 기존 Markdown과 함께 갱신해야 한다는 유지보수 주석을 둔다.

### `apps/web/src/app/manual/manual-copy-button.tsx`

- `'use client'` 경계를 갖는 작은 컴포넌트다.
- 전달받은 문자열을 `navigator.clipboard.writeText`로 복사한다.
- 복사 전, 성공, 실패 상태만 관리한다.
- 페이지 콘텐츠나 섹션 구조를 알지 못한다.

### `apps/web/src/components/shell/sidebar-shell.tsx`

- 사이드바 하단에 `/manual` 링크를 추가한다.
- `usePathname`으로 활성 상태를 정한다.
- 기존 주 메뉴 배열과 Draft 개수 표시 동작은 변경하지 않는다.

## 상호작용과 오류 처리

복사 버튼을 누르면 요청문 전체를 클립보드에 저장한다.

- 성공: 버튼 라벨을 잠시 `복사됨`으로 표시한다.
- 실패 또는 Clipboard API 부재: `복사하지 못했습니다. 직접 선택해 주세요.`를
  화면에 표시한다.
- 오류 객체나 클립보드 내용은 로그에 출력하지 않는다.
- 버튼은 키보드로 실행 가능하고 결과 메시지는 보조 기술이 읽을 수 있어야 한다.

페이지는 정적 콘텐츠이므로 로딩·데이터 오류 상태는 없다. 외부 상세 문서 링크는
새 창을 강제하지 않고 일반 링크로 제공한다.

## 접근성

- `h1`부터 하위 제목까지 문서 계층을 유지한다.
- 페이지 목차에 `aria-label`을 제공한다.
- 복사 버튼과 결과 메시지의 의미를 텍스트로 전달한다.
- 코드 블록은 키보드와 터치에서 스크롤할 수 있다.
- 활성 매뉴얼 링크는 색상 외에도 `aria-current="page"`로 구분한다.
- 기존 디자인 토큰을 사용해 명암 대비를 유지한다.

## 테스트

### 사이드바

- 네 개의 주 메뉴 항목과 순서가 그대로인지 확인한다.
- `사용 매뉴얼`이 하단 영역에 있고 `/manual`로 연결되는지 확인한다.
- `/manual`에서 `aria-current="page"`가 설정되는지 확인한다.
- 모바일 drawer에서 링크를 누를 때 닫기 동작이 유지되는지 확인한다.

### 매뉴얼 페이지

- `Topbar` 제목과 전체 주요 섹션이 존재하는지 확인한다.
- 신규 등록과 기존 정보 갱신 요청문이 존재하는지 확인한다.
- `init --detect`, `register --draft`, `status`, `diff`, `sync --draft` 명령이
  존재하는지 확인한다.
- 실제 서비스 배포와 DeployHub 자체 배포를 제외한다는 문구가 존재하는지 확인한다.
- 토큰을 대화에 붙여 넣지 말라는 안전 원칙이 존재하는지 확인한다.
- 목차 링크와 섹션 anchor가 일치하는지 확인한다.

### 복사 버튼

- Clipboard API 성공 시 전체 문자열을 복사하고 `복사됨`을 표시한다.
- Clipboard API가 없거나 거부되면 실패 안내를 표시한다.
- 실패 시 예외나 복사할 내용을 외부로 출력하지 않는다.

### 전체 검증

- 관련 Vitest 테스트
- `pnpm --filter web typecheck`
- `pnpm --filter web build`
- 데스크톱과 모바일 브라우저에서 `/manual` 접근, 목차 이동과 복사 동작 확인

## 완료 기준

- 로그인 사용자가 사이드바 하단 `사용 매뉴얼`에서 `/manual`을 열 수 있다.
- 기존 Markdown의 모든 사용자 안내가 앱 페이지에 제공된다.
- 신규 등록과 정보 갱신 요청문을 버튼으로 복사할 수 있다.
- 복사 실패가 비밀값이나 오류 객체를 노출하지 않고 안내된다.
- 데스크톱에서는 sticky 목차, 모바일에서는 상단 목차가 제공된다.
- 주 메뉴 네 항목의 구조와 Draft 개수 표시가 유지된다.
- 관련 테스트, 타입 검사와 운영 빌드가 통과한다.
