# DeployHub 프론트엔드 재디자인 — 설계

> 시각 언어를 DeployHub 자신의 개념에서 다시 끌어낸다. 선언과 관측의 구분을
> 화면 전체가 말하게 만든다.

**작성일:** 2026-07-29
**선행:** M1c·M2·M3 완료, UI 재설계(2026-07-28) 완료
**범위:** 매일 보는 네 화면 + 공용 부품 + 토큰. 설정 화면과 폼은 부품 교체로 따라온다.

---

## 1. 왜 고치는가

세 가지가 지적됐다.

**시각 언어가 DeployHub 것이 아니다.** `DESIGN-raycast.md` 는 제목 그대로 Raycast
마케팅 페이지를 분석한 문서다. 색·타이포·라운드가 전부 거기서 왔다. 내부 도구인데
마케팅 사이트의 토큰을 쓰고 있어서 `display-xl: 64px` 이나 `hero-stripe` 같은,
이 앱에 쓸 자리가 없는 항목이 남아 있다. 어둡고 깔끔해 보이는 이유는 있지만
이 시스템의 개념에서 나온 것이 아니다.

**개념이 화면에 안 보인다.** 이 시스템의 토대는 선언(`deployhub.yaml`)과
관측(수집기)의 구분이다. Drift 도, 판정도, "관측되지 않음" 규칙도 전부 거기서
나온다. 그런데 그 구분이 시각적으로 드러나는 곳은 프로젝트 상세의 구성도 한
군데뿐이다. 자원 표·타임라인·발견 화면은 둘을 섞어 보여준다.

**정보 위계가 애매하다.** 루트가 6열짜리 표인데 등록된 프로젝트가 하나다. 표는
수십 개를 훑을 때 쓰는 물건이고, 이 시스템은 그 규모가 아니다. 사용자가 알고
싶은 것은 "무엇이 무엇 위에서 돌아가는가" 인데 그 답이 상세 화면에만 있다.

## 2. 시각 방향 — 설계도

기계 도면에는 **그려진 선**과 **실측 주기**가 있다. 선은 "이렇게 만들어라" 이고
주기는 "재보니 이렇더라" 다. 엔지니어링 도면의 공칭치와 실측치가 이 시스템의
선언과 관측과 정확히 같다.

바탕은 어둡게 간다. CAD 뷰포트처럼 거의 검은 제도면에 잉크 흰색 선이다. 기존
토큰 값을 대부분 살릴 수 있고, 상태 색이 잘 드러나며, 새벽에 봐도 눈이 부시지
않는다.

## 3. 규칙 하나

```
web       Next.js  ┆ deployhub-web · running
└ 선언 ────────────┘ └ 관측 ──────────────┘
   실선, --line          점선 뒤, --annotation
```

**`┆` 왼쪽은 사람이 말한 것, 오른쪽은 기계가 본 것.** 이 규칙 하나를 네 화면에
똑같이 적용한다.

파생 규칙:

| 상황 | 표기 | 색 |
|---|---|---|
| 관측 없음 | `┆ —` | `--absent` |
| 선언 없음 (발견 화면) | 좌측 비움, 우측만 | `--annotation` |
| Drift | `┆ ≠ 관측값` | 색 없음. 기호로만 |

Drift 판별은 `packages/db/src/queries/drift.ts` 의 `computeDrift` 를 쓴다. 새로
만들지 않는다.

**관측 없음을 선언값으로 채우지 않는다.** M2 내내 지킨 규칙이고 코드에 이미
반영돼 있다. 이 재디자인은 그 규칙에 시각적 자리를 준다.

**Drift 를 경고색으로 칠하지 않는다.** 선언과 관측이 다른 것은 사실의 진술이지
장애가 아니다. 판정은 M3 가 따로 한다.

## 4. 토큰

### 4.1 새 토큰

```css
--canvas:      #07080a   /* 제도면 바탕 */
--paper:       #0d0d0d   /* 도면 블록 */
--grid:        #16181a   /* 격자 — 거의 안 보임 */
--rule:        #242728   /* 구분선 */

--line:        #f4f4f6   /* 선언 — 도면의 선 */
--line-mute:   #cdcdcd   /* 부차적 선언 */
--annotation:  #9c9c9d   /* 관측 — 실측 주기 */
--absent:      #6a6b6c   /* 관측되지 않음 */

--fault:       #ff6161   /* 장애 */
--caution:     #ffc533   /* 주의 */

--radius-card:   10px
--radius-button:  8px

--font-sans: Inter, "Noto Sans KR", system-ui, sans-serif
--font-mono: ui-monospace, "SF Mono", Menlo, Consolas, monospace
```

### 4.2 치환표

값은 대부분 그대로다. 이름만 바뀐다.

| 옛 이름 | 사용처 | 새 이름 | 값 |
|---|---|---|---|
| `--color-canvas` | 3 | `--canvas` | 동일 |
| `--color-surface` | 9 | `--paper` | `#0d0d0d` |
| `--color-surface-elevated` | 18 | `--paper` | `#0d0d0d` 로 접음 |
| `--color-surface-card` | 7 | `--paper` | `#0d0d0d` 로 접음 |
| `--color-ink` | 76 | `--line` | 동일 |
| `--color-body` | 41 | `--line-mute` | 동일 |
| `--color-mute` | 93 | `--annotation` | 동일 |
| `--color-ash` | 8 | `--absent` | 동일 |
| `--color-hairline` | 44 | `--rule` | 동일 |
| `--color-error` | 13 | `--fault` | 동일 |
| `--color-warning` | 11 | `--caution` | 동일 |
| `--color-success` | 8 | **삭제** | — |
| `--color-info` | 9 | **삭제** | — |
| `--radius-modal` | 0 | **삭제** | — |
| `--radius-badge` | 1 | `--radius-button` | 로 접음 |
| `--radius-row` | 1 | `--radius-button` | 로 접음 |

**`success` 와 `info` 를 없애는 이유.** 정상에 색을 주면 대부분이 정상이라 화면이
색으로 덮이고 진짜 경고가 묻힌다. M3 에서 이미 정한 규칙인데 토큰이 유혹으로
남아 있다. 정상은 `--line`, 미확인은 `--absent` 로 조용히 둔다.

**표면 3단계를 2단계로 접는 이유.** 세 값의 차이가 `#0d0d0d`·`#101111`·`#121212`
라 실제로 구분되지 않는다. 바탕과 도면 블록 둘이면 충분하다.

`success`·`info` 를 쓰던 17곳은 기계적 치환이 아니라 **각각 판단이 필요하다.**
대부분 상태 표시이므로 정상 계열은 `--line`, 나머지는 의미에 맞게 옮긴다.

## 5. 그리드

바탕 전체에 격자를 깔지 않는다. **도면 블록 안에만** 32px 격자를 넣는다.

```
페이지 바탕   민무늬 --canvas
도면 블록     --paper + 32px 격자 --grid
```

도면은 종이 위에 있고 나머지 UI 는 아니다. 전면 격자는 싸구려로 보이고, 표나
폼 위에서는 읽기를 방해한다.

격자는 CSS `repeating-linear-gradient` 로 만든다. 이미지를 쓰지 않는다.

## 6. 타이포

```
모노   구성요소 이름, 컨테이너 이름, 상태값, 도메인, 저장소, 수치, 절대 시각
산세   제목, 설명, 안내문, 라벨, 상대 시각
```

**웹폰트를 추가하지 않는다.** 지금 Inter 도 `@font-face` 없이 스택으로만 쓰고
있다. 모노도 시스템 스택으로 간다. 내부 도구에 폰트 다운로드를 얹을 이유가 없다.

크기 단계:

```
20px / 500   화면 제목
15px / 500   섹션 제목
14px / 400   본문
13px / 400   도면 안 값 (모노)
12px / 400   주기·라벨
```

`display-xl`(64px)·`display-lg`(56px) 같은 마케팅용 크기는 이 앱에 쓸 자리가
없으므로 뺀다. 최대가 20px 이다.

## 7. 화면

### 7.1 루트 `/`

프로젝트당 소형 설계도 하나.

```
 ● DeployHub                        2시간 전
 ──────────────────────────────────────────
  github  gnghkim/DeployHub
     └─┬ VPS Docker
       ├ web       ┆ deployhub-web · running
       ├ worker    ┆ deployhub-worker · running
       └ database  ┆ deployhub-postgres · healthy
          └ hub.…  ┆ SSL 65d

 ──────────────────────────────────────────
  등록되지 않은 스택 7 → 발견
```

위계:

1. 판정 점 + 프로젝트 이름 (가장 큼, 산세)
2. 구조 (모노, 들여쓴 트리)
3. 관측 (`┆` 뒤, `--annotation`)
4. 시각 (우측, `--absent`)

**표를 없앤다.** 프로젝트가 한 자릿수인데 6열 표는 맞지 않는다.

**미등록 스택을 루트에 나열하지 않는다.** 마지막에 개수와 링크 한 줄만 둔다.
관측만으로 프로젝트처럼 보이는 것을 막는 것이 이 시스템의 토대다.

**판정은 M3 의 `judgeStatus` 를 그대로 쓴다.** 새로 만들지 않는다.

**조회 수가 프로젝트 수에 비례하면 안 된다.** `listProjectsWithSummaryData` 가
지금 정확히 5회다. 구성요소별 관측을 루트에 그리려면 자원·컨테이너 이름이
필요해서 조회가 늘 수 있다. 늘리되 **상수로** 늘린다 — 한 번에 가져와 메모리에서
묶는다. 같은 파일이 `selectDistinctOn` 으로 배포와 이벤트를 그렇게 처리한다.

테스트로 단언한다: **프로젝트가 1개일 때와 10개일 때 발행되는 조회 수가 같다.**
기존 테스트에 같은 단언이 있으니 확장한다.

**지금 운영 데이터로는 도메인 줄이 비어 있다.** `domains` 테이블이 0행이고
`components.url` 이 전부 null 이다(등록 토큰 미발급). 위 그림의 `hub.… ┆ SSL 65d`
줄은 데이터가 생겼을 때의 모습이다. 데이터가 없을 때 그 줄이 사라져도 도면이
무너지지 않아야 한다.

### 7.2 프로젝트 상세 `/projects/[slug]`

이미 구성도다. 여기서는 `┆` 규칙과 격자를 입힌다.

M3 가 붙인 판정·근거·변경 이력은 도면 아래 주기로 정리한다. **구성도의 관측
자리를 판정으로 덮지 않는다.** 관측은 사실이고 판정은 해석이라 자리가 다르다.

### 7.3 발견 `/discovered`

선언이 없는 관측이다. 좌측을 비우고 우측만 있는 도면이 된다. 그 모양 자체가
"주인이 없다" 를 말한다.

```
  (선언 없음)  ┆ workwiki-backend · running
  (선언 없음)  ┆ workwiki-postgres · running
```

**경고색을 쓰지 않는다.** 주인이 없을 뿐 잘못된 상태가 아니다.

등록 안내문은 유지한다. 등록 버튼은 만들지 않는다.

### 7.4 변경 타임라인 `/events`

`이전 → 현재` 가 이미 주기 형태다. 값에 모노를 적용하고 severity 색만 남긴다.

`info` 는 색 없이 `--annotation` 으로 둔다. 대부분이 `info` 라 색을 주면 전부
켜져 있게 된다.

## 8. 지울 것

**`DESIGN-raycast.md` 를 지우고 `DESIGN.md` 를 쓴다.**

이것이 문제의 뿌리다. 설계 근거 문서가 다른 회사 마케팅 페이지 분석이면, 다음에
화면을 고치는 사람이나 AI 가 또 거기서 답을 찾는다. 새 문서는 위 3~7절을 규범
형태로 담는다.

## 9. 검증

토큰 치환은 기계적이라 **깨져도 기존 테스트가 잡지 못한다.** 화면이 렌더되기만
하면 색이 틀려도 통과한다. 그래서 다음을 명시적으로 확인한다.

1. 기존 테스트 572건 전부 통과
2. `git grep` 으로 옛 토큰(`--color-ink` 등) 잔존 **0건**
3. `--color-success`·`--color-info` 사용 **0건** — 정상에 색 쓰지 않기를 기계로 강제
4. `pnpm --filter web build` 통과
5. 모든 화면이 실제로 응답 (307 또는 200, 404·500 없음)
6. `md` 미만에서 도면이 가로 스크롤 없이 읽힘
7. 웹폰트 요청 0건 — `@font-face` 와 폰트 CDN 링크가 없는지 확인

6번이 중요하다. 트리 구조는 들여쓰기 때문에 좁은 화면에서 넘치기 쉽다.

## 10. 하지 않을 것

- 라이트 모드를 만들지 않는다. 지금 필요 없고 토큰을 두 배로 늘린다.
- 새 외부 의존성을 넣지 않는다. 그래프 라이브러리·아이콘 패키지·애니메이션
  라이브러리 전부 해당한다.
- 웹폰트를 추가하지 않는다.
- 설정 화면과 폼의 레이아웃을 재설계하지 않는다. 부품 교체로 따라오는 만큼만.
- 상태나 판정 규칙을 새로 만들지 않는다. M3 의 것을 쓴다.
- 등록 흐름을 바꾸지 않는다. AI 가 올리고 사람이 승인한다.
- 새 테이블이나 마이그레이션을 만들지 않는다.
- 데이터 조회 의미를 바꾸지 않는다. 이 작업은 표현만 바꾼다.
